# P(-1) Hardening Report — 2026-08-29 (v1.9.1)

**Scope**: full sweep across eight dimensions — command injection / input validation,
filesystem security, memory & buffer safety, syscall-return and error handling, plain
correctness, performance, test coverage, and a re-triage of every previously-deferred item.

**Method**: eight independent finders, each followed by an adversarial verifier instructed to
*refute* rather than confirm, with `live = true` (in `src/agnsh.cyr`'s include graph) required
before any finding could carry full severity. 93 findings survived verification. Every claim
below was then reproduced by hand against the built binary before any code was changed, and
re-verified after.

**Baseline**: 1.9.0 — 301 unit + 26 security + 59 smoke, binary 311,352 B, all gates green.
**Result**: 356 unit + 26 security + 59 smoke, binary 315,408 B, all gates green, **zero
compiler warnings** (the two long-standing ones are gone).

---

## Headline: the risk classifier was 100% dead on the SHELL_COMMAND path

**Severity: HIGH · live · both targets · `src/permissions.cyr:165` ← `src/commands.cyr:43`**

`split_command_line` emitted the command word and every argument as a **Str** fat pointer.
`analyze_command_permission` — and the entire permissions table behind it
(`get_command_basename`, `is_blocked_command`, `is_admin_command`, `is_write_command`,
`is_readonly_command`, `is_safe_command`, `has_system_path_arg`, `rm_has_dangerous_flags`) — is
**cstring-only**: `strlen(cmd)` + `load8(cmd + i)`. So it walked the 16-byte Str *header*
instead of the command text, every `streq` missed, and the function fell through to its
`return PermissionLevel.USER_WRITE` default for **every direct command line**.

Reproduced on the 1.9.0 binary before the fix:

| input | classified | audit record | correct |
|---|---|---|---|
| `dd if=/dev/zero of=/dev/sda` | `[MED]` | `"approved":1,"result":"proposed"` | BLOCKED |
| `mkfs /dev/sda1` | `[MED]` | `"approved":1,"result":"proposed"` | BLOCKED |
| `shred /etc/shadow` | `[MED]` | `"approved":1,"result":"proposed"` | BLOCKED |
| `su` | `[MED]` | `"approved":1,"result":"proposed"` | ADMIN |
| `cp /tmp/x /etc/passwd` | `[MED]` | `"approved":1` | SYSTEM_WRITE |

Consequences: the `WARNING: BLOCKED` and `Approval required` branches were **unreachable** for
this whole input class; the audit trail actively asserted that destructive commands were
auto-runnable; and `PermissionLevel.SYSTEM_WRITE` had no producer at all.

**Not an exec bypass today** — nothing executes on the SHELL_COMMAND path (host exec is only
`run /abs/path`; the agnos launchers gate on `is_safe_path` and never consult this classifier).
It was total failure of the sole risk classifier for that input class, and would have become an
approval bypass on exec wire-up.

**Fix**: convert at the boundary, once. `split_command_line` now emits NUL-terminated cstrings
via `str_cstr()`, matching what every other translator produces and what `Translation.command`
already was for the other 40+ translators. This simultaneously fixed the blank `"action":""`
field in every SHELL_COMMAND audit record and the raw-pointer bytes the terminal printed as the
command.

**Why the 301-test suite was green through all of it**: every test hand-stuffed a *cstring
literal* into `intent + 8` (`store64(sh_intent + 8, "ls")`) — the type the function wants —
while the parser supplied a Str. The unit tests validated the function in isolation against a
production integration that was broken. 17 further fixtures had the same inversion and were
corrected. New end-to-end anchors drive `Interpreter_parse` → `Interpreter_translate` and were
confirmed to **fail 8/9 against the pre-fix code** before being accepted.

## Findings fixed in 1.9.1

### Security — audit integrity

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | HIGH | Risk classifier dead on SHELL_COMMAND (above) | `str_cstr()` at the boundary |
| 2 | HIGH | **Audit logging silently dead on agnos.** `audit.cyr:54` called raw `sys_open(path, 1089, 384)` — the Linux shape. On agnos the signature is `sys_open(name, namelen, flags)`, so 1089 landed in `namelen` and 384 in `flags`. Malformed open on the primary target — the one platform where agnsh actually executes programs. | Route through `file_open`, the length-carrying ABI bridge that exists for exactly this |
| 3 | MEDIUM | **Audit log could be made unparseable by one byte.** `json_escape` copied bytes ≥ 0x80 through unvalidated, so a single high byte made the record invalid UTF-8 and therefore invalid JSON — and on a whole-file parse one poisoned line takes the entire log down. An actor whose own entry would read `rejected_safety` could trigger it deliberately. | UTF-8 **validated**, not blanket-escaped: well-formed sequences pass byte-exact (so `café` stays `café` rather than becoming `Ã©`), invalid bytes become U+FFFD. Overlongs, surrogates and out-of-range leads rejected |
| 4 | MEDIUM | **`json_escape` returned a cstring on its null path** (`return "\"\""`) where every other return is a Str, *and* carried two quote characters the caller also emits. `str_builder_add(sb, s: Str)` reads `load64(s+8)` as a length, so this was a `memcpy` of a garbage length. Reachable because `str_from` returns 0 on allocation failure | `return str_from("")`; annotated `fn json_escape(s): Str` — **which also cleared the two long-standing `assigning non-pointer to typed pointer` warnings** |
| 5 | MEDIUM | Audit write returns discarded — a short write on a full disk produced a corrupt (half-written) audit line reported as success | Both writes checked; `AuditLogger_log` returns −1 on a short write |

### Security — filesystem

| # | Severity | Finding | Fix |
|---|---|---|---|
| 6 | MEDIUM | **Symlink hijack of both state files.** With a symlink pre-placed at `$HOME/.agnsh_audit.log` or `$HOME/.agnsh_history`, the open followed it — and `sys_chmod` followed it too, so this was a *write plus re-permission* of an arbitrary user-owned file, one step worse than the "redirect the write" the v1.3.1 audit described. Reproduced, then confirmed closed | `O_NOFOLLOW` on both opens |
| 7 | MEDIUM | **History created world-readable.** `file_write_all` opened with a 0644-ish umask default and the chmod only tightened it *afterwards* — a create-then-chmod race exposing every command the user has typed, permanently if the process died in the window | Explicit `file_open` with mode 0600 **at create** |
| 8 | MEDIUM | History write return discarded, then chmod blamed — a full disk pointed the user at a permissions problem that did not exist | Write checked; distinct, accurate messages |

**On the `O_NOFOLLOW` deferral** — both stated blockers were stale. (a) The "needs a `lib/io.cyr`
API extension to thread custom flags" half: `file_open(path, flags, mode)` already exists.
(b) The "value differs per arch — `0o400000` on x86_64, `0o100000` on aarch64-generic" half is
**factually wrong and was the more dangerous error**: `asm-generic/fcntl.h` defines `O_NOFOLLOW`
as `(1 << 17)` = 131072 and *neither* x86_64 nor aarch64 overrides it (32-bit **arm** does — the
likely source of the confusion). `0o100000` = 32768 is **`O_LARGEFILE`**. An implementer
following the published guidance would have shipped an aarch64 artifact that opened the audit
log with `O_LARGEFILE`, leaving the race fully intact on half the release binaries while the
CHANGELOG claimed it closed. Corrected in `docs/guides/security-model.md` and recorded in
`src/sanitize.cyr` next to the constant.

### Previously-deferred items closed

All five MEDIUM findings deferred by the v1.3.1 P(-1) report "until the v1.4.0 wire-up" — a
wire-up that never happened across fifteen releases — are closed **in place**, independent of
any wire-up:

- `session.cyr:158,252` `SYS_CHDIR(str_data(dir))` ×2 → `str_cstr(dir)`
- `checkpoint.cyr:32` `sys_chmod(str_data(dir), 448)` → `str_cstr(dir)`
- `session.cyr:21,161,255` `SYS_GETCWD` return discarded ×3 → single checked
  `session_cwd_or_unknown()` helper returning `"?"` with a stderr warning

What made this cheap was `str_cstr()` shipping in the 6.5.36 stdlib — the deferral's real
blocker, though it was recorded as a wire-up dependency.

**Lint Category G** (also deferred, on false-positive grounds) is now anchorable and shipped: it
names the path-taking calls explicitly rather than matching `syscall(` broadly, so the legitimate
`sys_write(fd, str_data(s), len)` ptr+len shape is not matched. It caught exactly the 3 known
true positives and 0 false positives, and now guards the class.

### Performance

`history/add_at_cap` benchmark added (there was none), then fixed:

| benchmark | before | after | delta |
|---|---|---|---|
| `history/add_at_cap` | 17.506us | **298ns** | **−98.3% (58.7×)** |

`CommandHistory_add` rebuilt the *entire* entries vec — a fresh `vec_new` plus an n-element copy
— on every add once at capacity, which is the steady state for any real session (default cap
10000), and the discarded vec is never reclaimed. Now trims lazily against a slack margin:
O(1) amortized. `CommandHistory_save` clamps to `max_size` so the on-disk cap still holds.

⚠ **One honest regression**: `translate/cd` 112ns → 203ns (+81%). That is the cost of
`translate_change_dir` actually validating its path (finding #9) — it previously did no
validation at all. Correctness bought at 91ns; not hidden.

All other benchmarks unchanged within run-to-run jitter.

## Not fixed — bubbled to the roadmap

These are recorded as the **v1.9.x hardening arc** in `docs/development/roadmap.md`.

**Highest remaining, and the reason the arc exists:**

> **Every path that actually executes a program writes zero audit records.** `audit_one_shot` is
> reached only from `print_intent_result`, which runs only when *nothing* has executed. `run`,
> bareword launch, pipelines, redirection and background jobs all skip it. Verified: `agnsh -c
> 'run /bin/echo'` runs the program and creates **no audit file at all**. So the only actions the
> audit log records are the ones that never happened, while the entire real execution surface is
> invisible — and on agnos `owl /x > /.agnsh_audit.log` truncates the log with no record either
> time. Directly contradicts CLAUDE.md's "every command must be auditable".

Deferred here because it spans five launch sites that are almost entirely inside
`#ifdef CYRIUS_TARGET_AGNOS` and cannot be exercised on this host; landing it half-wired would be
worse than landing it deliberately. It is the first slice of the arc.

Also bubbled: the 64 KB history-load truncation; the `/tmp` state-file fallback; three
redirect/pipeline error-path defects (one-shot sentinel collision, job-table overflow leaking a
spawned child, discarded `exec_redirect` return); four parser-shadowing bugs (`delete user X`
being claimed by the REMOVE branch is the visible one — it emits `rm`); six measured
optimization opportunities including *why* `parse/shell_cmd` is 4× the next slowest parse; the
`run_agnos.cyr` parsers being untestable on the host; the coverage gate's denominator omitting
five modules that are in the binary; and nine latent defects in the non-compiled modules
(`prompt.cyr`'s 256-byte buffer handed to a `uname(2)` that writes 390 bytes is the sharpest).

## Method note — what to distrust next time

The adversarial verifiers refuted **0 of 93** findings. That is a weak signal, not a strong one:
it means the verification pass sharpened findings (correcting severity framing, catching an
incomplete fix sketch, flagging blast radius) rather than killing any. Findings were
double-counted across dimensions — the Str/cstring defect surfaced independently from four
different finders — so 93 findings is roughly 55 distinct root causes. Every finding acted on
here was reproduced by hand first; two agent claims were checked and **one was wrong** (the
per-arch `O_NOFOLLOW` split), which is the ratio to expect.
